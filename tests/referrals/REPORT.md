## 1. Схема системи

```
ГЕНЕРАЦІЯ КОДУ
  profiles.referral_code: default = 8 hex-символів із gen_random_uuid(), unique (0023)
  Користувач не може його змінити: після 0040 у authenticated немає UPDATE на цю колонку

ПОСИЛАННЯ
  /dashboard/referrals → `${NEXT_PUBLIC_APP_URL}/${locale}/login?ref=<code>` + кнопка «Скопіювати»

ЗАХОПЛЕННЯ
  login/page.tsx, вкладка «Реєстрація» (email+пароль):
    ref береться з window.location.search у момент сабміту → supabase.auth.signUp({ data: { ref } })
  ✗ Google OAuth і magic link ref НЕ передають
  ✗ ref ніде не зберігається (cookie/localStorage немає); зникає, щойно людина пішла з /login?ref=…
  DB-тригер handle_new_user (AFTER INSERT на auth.users, тобто ще ДО підтвердження email):
    шукає profiles.referral_code = ref (точний збіг, з урахуванням регістру)
    → profiles.referred_by = реферер, у referrals додається рядок (pending), referred_id unique

НАРАХУВАННЯ (webhook /api/billing/webhook, лише status=paid, лише один раз на payment)
  якщо у платника є referred_by:
    reward = round(payment.amount × 10 %) у копійках (amount — сума ПІСЛЯ знижки кредитом)
    accrue_referral_reward(): рядок у referral_earnings (unique payment_id) → баланс
       звичайний реферер → credit_balance_kop
       амбасадор (is_ambassador) → cash_balance_kop
    referrals.status pending → converted (перший платіж)
  Рахуються будь-які платежі: галерея, сайт, місяць, рік, promo_autopay

ВИТРАТА
  Кредит: у /api/billing/checkout (інтерактивна оплата), якщо не йде промо-місяць імпорту:
    знижка = min(floor(credit/100) ₴, ціна − 1 ₴) → payments.credit_applied_kop
    webhook paid → consume_credit() (не нижче 0)
  ✗ автопродовження (cron /api/billing/renew) кредит НЕ використовує
  Готівка (амбасадор): request_withdrawal() від 200 ₴; увесь баланс іде в заявку →
    адмін у /dashboard/stats позначає «виплачено» / «відхилено» (відхилено = гроші повертаються на баланс)
  Застаріле: pending_free_months (v1) досі читається в cron, але ніщо його не нараховує

ЩО БАЧИТЬ КОРИСТУВАЧ
  /dashboard/referrals: посилання, «Запрошено», «Стали платними», «Ваш кредит» / «Готівка до виплати»,
    для амбасадора — форма виведення
  Лендинг: секція «Реферальна програма» (uk/en)
  Листи Brevo: у реферальній системі немає ЖОДНОГО
  Адмін (/dashboard/stats): кількість рефералів, скільки з них платних, увімкнення амбасадора, заявки на виплату
```

### Правила, закодовані в коді

| Правило | Значення | Де |
|---|---|---|
| Розмір винагороди | 10 % від **кожного** успішного платежу запрошеного, без обмеження в часі | `webhook/route.ts` `REFERRAL_RATE` |
| База для % | фактично сплачена сума (після знижки кредитом і бандлу) | `payment.amount` |
| Потрібна оплата запрошеного? | так; Free або реєстрація без оплати = 0 | webhook |
| Кому | тільки рефереру (запрошений бонусу не отримує) | — |
| Форма | звичайний фотограф — кредит; амбасадор — гроші | `accrue_referral_reward` |
| Ліміти | немає (ні стелі на суму, ні на кількість запрошених) | — |
| Витрата кредиту | тільки при ручній оплаті; залишається щонайменше 1 ₴ до сплати; не діє під час промо-місяця імпорту | `checkout/route.ts` |
| Виведення грошей | лише амбасадор, від 200 ₴, увесь баланс однією заявкою, виплата вручну | `request_withdrawal` |

| Амбасадор | тариф Про + Сайт Плюс на 10 років | `setAmbassador` |

## 2. Розбіжності з очікуваною поведінкою

Правила в розділі «Очікувана поведінка» не були заповнені (там лишився плейсхолдер). Тому
специфікацією тут вважаються обіцянки з лендингу й кабінету: «10 % з кожної оплати, щомісяця,
кредит автоматично зменшує наступний рахунок».

1. **«Щомісяця»** не виконується для автопродовження Monobank: синхронно успішне
   списання в cron винагороди не нараховує (BUG-01).
2. **«Кредит автоматично зменшує наступний рахунок»** не виконується для підписки з
   автоплатежем: cron списує повну ціну, кредит росте без кінця (BUG-02).
3. **Посилання працює** лише за реєстрації email+паролем одразу на сторінці з посиланням (BUG-03).
4. Refund не скасовує винагороду (BUG-04). Чи це задумано, вирішувати тобі.
5. Запрошений нічого не отримує. Якщо задумано «обидва отримують бонус», цього немає
   (старий v1 з двостороннім безкоштовним місяцем прибраний).
6. Листів Brevo про реферали немає зовсім (BUG-08).

**Треба вирішити тобі** (від цього залежить частина фіксів):
чи отримує бонус запрошений; чи потрібна стеля 10 % (кількість місяців або сума);
чи допустимий самореферал; як поводитися при refund; чи рахувати платежі за сайт.

## 4. Ручний чек-лист для проду (платіж 129 ₴)

Потрібні: акаунт **A** (реферер, твій) і новий email для **B** (запрошений), бажано в
інкогніто. SQL запускати в Supabase → SQL Editor.

1. **A** → `/uk/dashboard/referrals`. Посилання має вигляд `https://proiav.space/uk/login?ref=xxxxxxxx`.
   Натисни «Скопіювати» → кнопка «Скопійовано ✓», вставлене в нотатки посилання збігається. Перевір і на телефоні.
   Статистика: 0 / 0 / 0 ₴. Перемкни `/en/dashboard/referrals`: тексти англійською, посилання `/en/login?ref=…`.
2. **Негатив (без оплати):** відкрий посилання в інкогніто, натисни «Продовжити з Google» новим
   Google-акаунтом → очікувано (BUG-03) прив'язки НЕ буде:
   `select referred_by from profiles p join auth.users u on u.id=p.user_id where u.email='<google email>';` → null.
3. **B:** відкрий посилання в інкогніто → вкладка «Реєстрація» → email + пароль → підтверди лист.
   `select p.referred_by, r.status from profiles p left join referrals r on r.referred_id=p.user_id join auth.users u on u.id=p.user_id where u.email='<B>';`
   → referred_by = id акаунта A, status = pending. У A «Запрошено» = 1.
4. **B** → Тарифи → «Базовий», місяць → Monobank показує **129 ₴** → оплати.
5. Після редиректу: у B тариф «Базовий». SQL:
   `select status, amount, credit_applied_kop from payments where user_id=(select id from auth.users where email='<B>') order by created_at desc limit 1;` → paid, 129, 0
   `select amount_kop, kind from referral_earnings where referred_id=(select id from auth.users where email='<B>');` → **1 рядок: 1290, credit**
   У A: «Стали платними» = 1, «Ваш кредит» = **12,90 ₴**.
6. **Повторна доставка:** у кабінеті Monobank повтори webhook для цього інвойсу, якщо є така опція
   (або почекай ретраї). Запит із кроку 5 має повертати так само 1 рядок, у A так само 12,90 ₴.
7. **Витрата кредиту A** (необов'язково, ще ~116 ₴): A → «Базовий» → Monobank має показати **117 ₴**, в описі «(кредит −12 ₴)».
   Після оплати `credit_balance_kop` у A = 90. Якщо не платиш, закрий сторінку: кредит лишається 1290.
8. **Refund:** поверни платіж B у кабінеті Monobank. Очікувано з BUG-04: payments.status = canceled,
   а у A кредит **лишається** 12,90 ₴. Зафіксуй, що саме побачила.
9. **Прибрати за собою:** у B «Скасувати автопродовження» (інакше через місяць cron спише 129 ₴ зі збереженої картки):
   `select status from billing_subscriptions where user_id=(select id from auth.users where email='<B>');` → canceled.
   Якщо робила крок 7, зроби те саме для A.
10. **Листи:** жодного реферального листа не має прийти ні A, ні B. Приходить лише стандартне підтвердження реєстрації від Supabase.
