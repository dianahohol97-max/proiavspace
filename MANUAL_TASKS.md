### 0. Сповіщення застосунку «проЯв» на телефоні (ключі VAPID)
Без ключів застосунок працює, але сповіщення не надсилаються (у налаштуваннях
кабінету пише «Сповіщення ще не налаштовані на сервері»).
1. На своєму комп'ютері в папці репозиторію: `npx web-push generate-vapid-keys`
   — покаже Public Key і Private Key.
2. Vercel → Settings → Environment Variables (Production), додати:
   - `VAPID_PUBLIC_KEY` — Public Key;
   - `VAPID_PRIVATE_KEY` — Private Key (секрет!);
   - `VAPID_SUBJECT` — `mailto:hello@proiav.space` (можна не додавати — це значення за замовчуванням).
3. Ключі не міняти без потреби: нова пара вимикає всі наявні підписки, фотографам
   доведеться ввімкнути сповіщення ще раз.
4. Міграція `0068_push_notifications.sql` має бути застосована до мержу `release/4` у `main`.

## 🟡 CDN через Cloudflare Worker (щоб фото швидко відкривались з будь-якої країни)
Прев'ю, тумби й постери (`…/v/…`) роздає Cloudflare Worker `ops/cdn-worker` з кешем. Бакет B2
**лишається приватним**: Worker сам підписує запити ключем лише на читання. Оригінали (`…/o/…`),
лого й усе інше Worker не віддає (404), застосунок дає на них підписані посилання на B2, як і раніше.
Поки `MEDIA_CDN_URL` не задано, усе працює як зараз (підписані посилання з B2).

⚠️ Бакет **не** робити Public, а Bunny Pull Zone на публічний бакет **не** створювати: це
відкрило б оригінали за прямим посиланням (CL-04 в `docs/AUDIT_STORAGE_LIFECYCLE.md`).

Покроково: **`ops/cdn-worker/README.md`**. Коротко:
1. Акаунт Cloudflare (Free) → Workers & Pages → вибрати піддомен `workers.dev`.
2. Backblaze → Application Keys → новий ключ **Read Only** лише на бакет медіа, prefix `u/`.
3. Задеплоїти Worker (`npx wrangler@4 deploy` або вставити `ops/cdn-worker/dist/worker.js` у
   дашборді), додати змінні `B2_BUCKET`, `B2_REGION` і секрети `B2_KEY_ID`, `B2_APPLICATION_KEY`.
4. Перевірити: прев'ю через `https://proiav-media.<піддомен>.workers.dev/<ключ>` відкривається,
   ключ з `/o/` дає 404.
5. Vercel → **dianatracker-dtks** → `MEDIA_CDN_URL` = адреса Worker → Redeploy (або мерж релізу).

## 🟡 Емейл-розсилка (завтрашнє завдання)
Щоб клієнти отримували лист «фото готові», а я — сповіщення про броні.

1. Акаунт на [brevo.com](https://www.brevo.com) → Senders, Domains & Dedicated IPs →
   **автентифікувати домен** (додати DNS-записи, які Brevo покаже: код Brevo, DKIM, DMARC).
2. Vercel env: `BREVO_API_KEY` (SMTP & API → API keys) і `EMAIL_FROM`
   (напр. `проЯв <hello@proiav.space>`) → Redeploy.
   Перевірка: під адмін-акаунтом `POST /api/admin/test-email` з `{"to": "твоя@пошта"}`.
3. Supabase → Authentication → Emails → **Custom SMTP** — щоб листи
   підтвердження пошти теж ішли з мого домену, а не з дефолтного Supabase
   (Brevo SMTP: `smtp-relay.brevo.com`, порт 587, логін і SMTP-ключ — з
   Brevo → SMTP & API → SMTP; це окремий ключ, не `BREVO_API_KEY`).
