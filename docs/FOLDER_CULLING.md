# Відбір із папки (RAW, до обробки)

Сторінка кабінету `/[locale]/dashboard/cull` («Відбір із папки», працює без галерей; пізніше — окрема підписка).
Демо без бази для замірів і e2e: `/uk/cull-demo` (noindex; `?opfs=<тека>` — запис через приватну ФС браузера).

**Файли не завантажуються на сервер.** Усе — у браузері фотографа: з кожного RAW читаються лише
заголовки (~2 КБ) і байти вбудованого JPEG-прев'ю (`File.slice`), RAW не декодується.

## Вибір папки
- Chrome/Edge: File System Access (`showDirectoryPicker`), дескриптор зберігається в IndexedDB — після
  перезавантаження «Продовжити» без повторного вибору; запис .xmp прямо в папку (окремий дозвіл «зберегти зміни»).
- Safari/Firefox: `<input webkitdirectory>` (лише читання) → результат як ZIP із .xmp + README + CSV.
- Підтеки до 4 рівнів (DCIM/100CANON…); RAW+JPEG з однаковою назвою — один кадр (RAW).

## Формати (`src/lib/folder-cull/raw/`, власний парсер, без бібліотек)

| Формат | Де прев'ю | Перевірено на реальному файлі (raw.pixls.us, CC0) |
|---|---|---|
| CR2 | IFD0: JPEG-смуга (Compression 6) | 5D Mark IV — 6720×4480 |
| CR3 | ISO-BMFF: `PRVW` (1620×1080) + повнорозмірна JPEG-доріжка (`trak`/`co64`) | EOS R6 — 1620×1080 / 3408×2272 (crop) |
| NEF | SubIFD: JPEGInterchangeFormat | Z 50 — 1620×1080 / 5568×3712 |
| ARW | IFD0: JPEGInterchangeFormat | ZV-E10 — 1920×1080 |
| RAF | заголовок Fuji (зміщення 84/88) | X-T50 — 4416×2944 |
| DNG | SubIFD NewSubfileType=1, JPEG-смуга | DNG Converter (5D III) — 1024×683 / 5760×3840 |
| ORF | maker note OM/Olympus → CameraSettings 0x2020 | OM-3 — 3200×2400 |
| RW2 | IFD0 JpgFromRaw (0x2E) | G9 — 1920×1440 |
| JPEG | сам файл | — |
| HEIC | декодує лише Safari (`createImageBitmap`); в інших браузерах — «не відкривається» | — |

Кожен кандидат перевіряється за власним SOF: беруться лише baseline/progressive JPEG (лосслес-смуга CR2 —
ні). Для аналізу — найменше прев'ю з довшою стороною ≥ 1000 px, для 100 % — найбільше. Час зйомки:
DateTimeOriginal + SubSecTimeOriginal (RAW, або EXIF усередині JPEG для RAF/RW2). Орієнтація RAW
застосовується до прев'ю; якщо JPEG має власну EXIF-орієнтацію (RAF), її застосовує декодер — без подвійного повороту.
У репозиторії — синтетичні контейнери тих самих структур (`tests/folder-cull/make-raw.ts`), реальні RAW по 6–125 МБ не комітяться.

## Аналіз
Той самий, що в галереях: різкість серед схожих, серії (dHash + **час зйомки**, ≤ 15 с), кращий у серії,
заплющені очі (MediaPipe з `/vendor/mediapipe`). Пул воркерів `min(6, ядра−1)`, пауза на прихованій вкладці,
скасування, прогрес/ETA; сесія (виміри, мініатюри, рішення) у IndexedDB — можна продовжити після перезавантаження.
Очі: GPU-делегат, якщо GL апаратний; на програмному GL (SwiftShader/llvmpipe) — CPU (у 1,7× швидше), два воркери.

**Брак** = розмито або заплющені очі (повтори в серіях — за налаштуванням). Ручні позначки сильніші:
P рятує кадр, X бракує, зірки знімають авто-брак.

Клавіші (як у Photo Mechanic): ←→↑↓, **P** — залишити, **X** — брак, **U** — зняти прапорець, **1–5** — зірки,
**0** — без зірок, **Enter** — на весь екран, **Z** — 100 % (у точці кліку, перетягування), **S** — серія, **Esc**.

## Що пишеться в .xmp і чому

| Поле | Значення | Хто читає |
|---|---|---|
| `xmp:Rating` | `-1` брак; зірки (кращий у серії — 3★ за замовчуванням) | Rating 0–5: Lightroom Classic, Capture One, Bridge. `-1` = «Rejected» за специфікацією XMP (ISO 16684-1) і для Bridge; **Lightroom Classic -1 як відхилення не сприймає** (імпортує як «без зірок») |
| `xmpDM:pick` / `xmpDM:good` | `-1`/`False` брак, `1`/`True` залишити (P) | Lightroom Classic **13.2+** («Support to read and write flag states to XMP»). Старіші версії прапорці з XMP не беруть |
| `xmp:Label` | `Red` для браку (налаштовується; можна й мітку для серій) | Lightroom Classic (стандартний набір міток, англійські назви), Capture One, Bridge |
| `xmp:MetadataDate` | час запису | щоб Lightroom помітив зміну файлу |

Тому брак дублюється: прапорець (LrC 13.2+) + червона мітка (старі LrC і Capture One, де прапорця немає).
Вимога: назва sidecar — `IMG_0001.xmp` (базове ім'я, як пише Lightroom).

Наявний .xmp **не перезаписується**: змінюються лише наші атрибути/елементи на місці, решта (налаштування
обробки, ключові слова) — байт у байт. Перед кожним записом файли перечитуються з диска. Якщо рішення змінилось,
наші значення відкочуються до тих, що були у файлі до першого запису (`original` у сесії).
JPEG/HEIC: Lightroom окремих .xmp для JPEG не читає — для них CSV і «Скопіювати назви браку».

**Не перевірено в живих програмах** (немає Lightroom/Capture One у середовищі розробки) — потрібна ручна перевірка:
імпорт папки з нашими .xmp у LrC 13.2+ (прапорець Rejected, зірки, червона мітка), у старішій LrC (мітка, зірки),
у Capture One (зірки, мітка); «Прочитати метадані з файлів» для вже імпортованої папки. Чи Capture One читає
`Rating=-1` — у документації не знайдено.

Джерела: XMP Specification Part 1 / ISO 16684-1 (xmp:Rating −1 = rejected); реліз-ноти Lightroom Classic 13.2
(flag states у XMP) і обговорення в спільноті Adobe; exiftool XMP-xmpDM (теги Pick, Good); форуми FastRawViewer
і Capture One (Rating −1 лише в Bridge; мітки в C1).

## Швидкість (контейнер 4 ядра, Chromium headless, прод-збірка)

| | 1000 файлів | 3000 файлів |
|---|---|---|
| Вибір папки (сканування) | 0,4–0,6 с | 1,3 с |
| Прев'ю + різкість + dHash + мініатюра (реальні RAW 8 форматів) | 28–29 с (~29 мс/файл) | 88–93 с |
| + очі (CPU ×2) | +40 с (усього 68 с) | +125 с (усього 216 с) |
| Те саме при CPU 4× (головний потік) | 45 с без очей | — |
| Запис .xmp у папку (нові) | 0,8 с | 2,8 с |
| Повторний запис (перечитати + оновити) | 2,1 с | 7,8 с |
| ZIP із .xmp (Safari/Firefox) | 2,0 с | 6,2–6,8 с |

Головний потік: без довгих задач на 1000; на 3000 з очима — поодинокі до ~90 мс.
